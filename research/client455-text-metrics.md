## Реализованное поведение

`RF455_TextWidth` сохраняет побайтовый prefix, включая разрыв DBCS-пары.
Null или нулевая длина возвращают0, FFFF выбирает всю строку. Вместо общей
неограниченной scratch-области эталона используется собственное хранилище.
Unsafe overflow, foreign pointers и огромные входы этим не сертифицированы.

`RF455_TextFitBytes` использует текущий GDI DC и GetTextExtentExPointA, затем
языковой provider для проверки последнего lead byte. Он проверен внутри
full-object probe; обычный production caller появится с переносом TextBoard.
Неиспользуемый fit helper пока удаляется линкером из production PE.

`RF455_DefaultTextHeight` измеряет именно пустую строку, а не условную букву.
Если GDI возвращает нулевую высоту, backend использует высоту ячейки, как
подтверждено для текущей ветви455. Первое значение сохраняется при смене шрифта.

Обычный `CGUIText::SetString` теперь вызывает пересчёт размеров. При style
80000000 промежуточный размер8*WORD(width/12),16 затем перезаписывается обычным
width/height, если отсутствует40000000. При40000000 конечный размер равен
16*WORD(width/12),32. Эта особенность подтверждена инструкциями, не исправлена
на предполагаемое «правильное» поведение. SetFont сам размеры не меняет.

## Адаптация ранней инициализации старого клиента

Первая собственная PE `19821d65…` завершилась до main с чтением адреса10,
own RVA5F034. Трасса сохранена в
`work/m9/19821d65/text-metrics-ko-kr-001/metric-debug.jsonl`. Причина: глобальные
GUI-конструкторы0.7 вызывают SetString до конструирования GDI font provider.

Вместо выдуманного размера или фиксации нулевой первой высоты добавлена очередь
собственных ранних запросов геометрии. После успешного создания шрифта они
пересчитываются. Деструктор CGUIText удаляет ожидающий объект; состояние очереди
защищено от обращений поздних глобальных деструкторов. Backend хранит только
callback и не получает обязательной зависимости от GUI. Это адаптация lifecycle
исходной базы0.7, **не утверждение о наличии такой очереди в эталоне455**.

Native fixture создаёт строку в глобальном конструкторе, а также создаёт и
удаляет временную раннюю строку. После реального создания шрифта проверяет
полученные размеры; оба профиля завершаются естественным exit0.

## Проверки и сборка

`probe_client455_text_metrics.py` собирает собственный console entry с настоящими
обычными клиентскими объектами. Для Korea/Russia используются реальные
NDLanguage и шрифты, viewport640×480 и D3D9. Независимый DC выбирает фактический
HFONT; oracle вызывает Win32 GetTextExtentPoint32A/GetTextExtentExPointA напрямую.
Проверены byte prefixes, включая обрыв DBCS, диапазон ширин от-1 до полной+2,
геометрия настоящего CGUIText, сочетания style flags и отсутствие пересчёта при
SetFont. Reload шрифта на16points подтверждает сохранение первой высоты.

Korea:50 prefix cases/260 fit cases; Russia:48/276. Это локальные сравнения,
не мера готовности клиента. На кадрах271/304 изменённых пикселя соответственно.
Ранние кадры содержали mojibake из-за UTF-8 wide literals при legacy source
codepage компилятора. Fixture исправлена универсальными Unicode escapes и
проверкой codepage roundtrip. Только финальные кадры из текущего native report
приняты и просмотрены: читаемые «Wi 가나다 455» и «Wi Привет 455».
