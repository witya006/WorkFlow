# Замена карты в клиенте — 13.11.2026

При межкартовом переходе прежний обработчик очищал сцену, вызывал
`CLand::LoadLevel` и продолжал даже при отказе. Сама загрузка проверяла
расширение уже после освобождения старого уровня. При ошибке клиент мог
применить координаты назначения к пустой сцене.

В `f4f22ad3…` общий загрузчик проверяет путь, версию и достаточный
размер BSP до замены уровня. Проверяется файл, который читает движок
через `MapPath`. Каталог из закреплённого `Map.edf` содержит 110 путей
с расширением `.bsp`. Эталонный загрузчик по RVA `0x3c8600` и стадия
перехода по RVA `0x2d5b0` привязаны к x86 455
`b1b5febf0d0394712e2322350e19dafe60742e8642697b93cfb89135bac1fd8b`.
[Исследование загрузчика](../inventory/client455-world-reference.json) ·
[Исследование перехода](../inventory/client455-base-portal-reference.json).

При ошибке до очистки сцена остаётся загруженной. Если клиент уже
начал подтверждённый переход и больше не может открыть карту, он
закрывает экран загрузки и вызывает штатный выход при разрыве связи.
Координаты назначения и подтверждение прибытия в этой ветке пропускаются.
Эта ветка пока проверена по исходникам. Загрузка вспомогательных ресурсов
движка остаётся отдельным этапом.

В Direct3D пропущены отсутствующий BSP, неподдерживаемый INS и BSP
с полным заголовком и усечёнными данными. Во всех трёх случаях
сохранились указатель, память и кадр Bellato. Загрузчик затем привязал
NeutralB и отрисовал её через камеру карты. Память движка вернулась
к исходному счётчику после освобождения. Оригинальный комплект по-прежнему
не содержит `trade_bel.r3e`, на который ссылается NeutralB. Стенд
воспроизвёл это предупреждение.

## Сетевой запрос обычного портала

В эталоне 455 ввод проходит через RVA `0x2d0c0`. Отправитель по RVA
`0x1802c0` передаёт `8/1` с семью байтами. Первый байт содержит
индекс портала, следующие три WORD предназначены для серийных номеров
предметов. Маршрут по RVA `0x1801b0` принимает `8/2`. При успехе
обработчик по RVA `0x180480` берёт индекс карты из байта 1, три
`float` с байта 2 и режим зоны из байта 14. Режим 0 использует связь
из каталога. Режимы смены зоны и принудительного перехода идут по
другим веткам.
[Разбор x86 455](../artifacts/client455-progress/ordinary-map-portal-reference.json).

В `9b62d01a…` при переходе без предметов клиент заполняет свободные
WORD значением `0xffff`. Пока ожидается ответ, текущая карта и портал
сохраняются. Отказ снимает ожидание и показывает сообщение из языкового
каталога. Успех сверяет карту назначения и запускает штатную смену карты.
При несовместимом подтверждённом переходе используется выход при разрыве
связи, чтобы клиент не продолжал игру с несогласованной позицией.

Проверка штатного обработчика использовала `Map.edf` и буфер отправки
клиента. Прошли NeutralB → NeutralB и NeutralB → Resources до этапа
загрузки, включая координаты с дробной частью. Только межкартовый
сценарий открыл экран загрузки. Отдельно прошли отказ по дистанции,
отмена, поздний и повторный ответы, ошибка отправки и отсутствующий
BSP назначения. Сборка Win32 и ранний запуск Taiwan прошли.
[Манифест проверки](../inventory/client455-ordinary-map-portal-checkpoint.json).

Открыты загрузка Resources и движение после прибытия в одном прогоне с
живым сервером, передача между зонами и порталы с расходуемым предметом.

## Прибытие и движение на Resources

В `59b6f605…` подтверждённый переход сбрасывает ожидание движения и
остановку с исходной карты. Клиент сохраняет последовательность исходящих
запросов. Поздний ответ остановки в процессе загрузки больше не ставит
в очередь перемещение к старым координатам. Прибытие отправляется по
`3/1`. Путь отправки сверён с RVA `0x2db10` закреплённого x86 455.
Если отправка возвращает ошибку, клиент сохраняет запрет движения и
переходит к штатному выходу при разрыве. Эта ветка пока проверена по коду.
[Разбор эталона](../artifacts/client455-progress/map-arrival-reference.json).

Стенд загрузил настоящие NeutralB и Resources с устройством Direct3D,
использовал связь портала 2 → 13 из `Map.edf` и пропустил ответы стенда
через штатный клиентский диспетчер. После `8/2` загрузилась Resources,
аватар получил её координаты, а клиент отправил `3/1`. После `3/2`
первый запрос `4/1` содержал координаты Resources и номер 2. Ответ
`4/4` перевёл аватар в движение, один кадр продвинул его на 3 единицы.
Поздний ответ `4/20` пришёл во время перехода и не поставил движение
к старой карте. В стенде интервалы ожидания проходили через установку
счётчика этапа. Порядок состояний и сообщений проверен в одном процессе.
[Манифест проверки](../inventory/client455-portal-arrival-native.json).

Ранний запуск Taiwan и компонентные проверки обычного портала и Return
из панели прошли на той же сборке. Прогон на живом сервере остаётся
открытым. При загрузке NeutralB сохранилось известное предупреждение
о ресурсе `trade_bel.r3e`.
