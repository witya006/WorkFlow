## Перенесённые контракты

- `CProcessMagic`: 3004 байта, 64 дорожки по 46 байт с offset 60. Поле состояния
  DWORD на offset 4; axis bytes 9/10; управляющая структура 24 байта на offset 36.
- Parser использует обычный ресурсный FILE, останавливается на `end`. Это важно:
  ресурсный FILE позиционирован в архив, а его физический EOF остаётся концом
  архива. Добавлены axis, blur, parabola/multi; billboard устанавливает оба
  целевых бита. Control slots 61–63 и наследуемые перекрытия Rand1/Rand2 сохранены.
- Узел кривой занимает 28 байт; восстановлены вставка перед хвостом и изменение
  хвоста, BYTE count/multiple, unsigned delay с верхней границей 1000. Пустой
  target Destroy не заменён придуманным освобождением узлов.
- Временная выборка делит frames на 30, использует включённую старую и исключённую
  новую границу. У пустого скрипта очищает только младший байт состояния. Последнее
  сравнение сохраняет наблюдённый результат для NaN.
- Обнаружена обязательная общая зависимость: `EffectInfo` 56 байт вместо старых
  48. Добавлены два DWORD на 48/52; конструктор задаёт 0 и FFFFFFFF. Их смысл и
  остальные producers пока неизвестны. Начальный common prefix сохранён.
  `CMagicList` вследствие этого занимает 456 байт вместо 448; EffectInfo на 388.
- Обычный кэш проверяет существование архивного ресурса и отказывает при нуле
  дорожек. Все выбранные методы берутся из собственных клиентских object files,
  управляющий код — из facade. Legacy варианты этих методов из engine не выбраны.

Старые engine extension headers всё ещё содержат прежние определения 16/48.
Это не полная приёмка частного ABI: необходимо проверить остальных потребителей.
Для 65-й дорожки собственный parser явно отказывает до выхода за границу и
закрывает FILE через RAII; unchecked overflow оригинала не воспроизводится.
