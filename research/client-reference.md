# Закреплённый клиент и различия двух файлов

Эталон поведения: текущий RF_Online.bin пользователя, SHA-256
b1b5febf0d0394712e2322350e19dafe60742e8642697b93cfb89135bac1fd8b.
Архитектура x86, image base 0x400000. Выбор закреплён config/client-target.json.
Обозначение «455» — целевой комплект пользователя, не независимо доказанная атрибуция.
Backup сохранён как дополнительный материал, а не замена целевого поведения.

Оба файла по 8 430 808 байт скопированы в work/client-reference с проверкой SHA-256.
Во всём файле только 5 различных байтов в 2 диапазонах. Скрипт
compare_client_binaries.py сохраняет смещения и RVA в inventory/client-binary-comparison.json.

## Подтверждено статическим анализом

- В .text изменена инструкция в функции sub_7A67E0 (VA 0x7A67E0, RVA 0x3A67E0).
  Она относится к ветвлению вокруг проверки срока клиента; это следует из дизассемблирования,
  вызова GetLocalTime и связанных сообщений. Никаких новых изменений EXE не выполнялось.
- В .rdata изменены 4 байта double по VA 0xAAF748 / RVA 0x6AF748: приблизительно
  4.151 в backup и 4.55 в текущем файле. Значение используется не только для строки UI:
  у него есть ссылка из sub_526030 (VA 0x526030, RVA 0x126030), где выполняется сравнение.
  Поэтому считать это чисто косметическим изменением нельзя.
- Значение в UI не доказывает наличие всех функций версии. Смысл сравнения в sub_526030
  пока не установлен; выводов о происхождении и полноте версии из него не делаем.

IDA/Hex-Rays проверены на backup-клиенте. База сохранена под work/, собственная сессия
4ffd6991 закрыта с save=true. Начальный idb_open превысил таймаут 300 секунд, однако
после окончания анализа idb_list обнаружил готовую сессию; повторная загрузка не понадобилась.
Код и полная декомпиляция в artifacts/client-reference-function.json, вне Git.
Ни один клиентский EXE не запускался. Декомпиляция — вспомогательное представление;
ключевые выводы сверены с инструкциями и ссылками.

## Остаётся

Полный хеш-манифест ресурсов, подтверждение семейства сборки, анализ дополнительного
сравнения по версии и проверки поведения в контролируемом стенде. Для M2 закреплены
бинарный эталон и точные различия; это не завершённый реверс клиента.
