## Восстановленное поведение

Сообщения2/3 объединяют сегменты по сериализованной длине с `_mbsnbcpy`,
сохраняя дополнение нулями после embedded NUL. Затем открывают диалоги с
ID6000/6002, style3/4, alpha B0 и duration FFFFFFFF. Это реальный GUI consumer;
его устаревшая отрисовка пока не соответствует всем деталям455.

Текстовый буфер исходного метода имеет1024байта. Новый код проверяет границу
1023байта содержимого и отказывает при переполнении, не повреждая результат.
Это явно ограниченная область соответствия. Проверены embedded NUL, граница,
превышение, одиночный DBCS lead и полная пара при codepage949.

Панель принимает события только с window ID38. При первом событии общий
таймер инициализируется отдельным чтением часов, затем время читается снова.
Отчёт запрашивается только при unsigned elapsed **строго больше60000**.
Переполнение DWORD проверено. Состояние таймера общее для панелей.

Скрытое briefing window записывает input3. Общий cooldown уменьшается только
при положительном значении, даже когда обучение пропущено. Запрос выхода
требует cooldown0, quitRequested, отсутствия busy и ненулевого ordinal задания.
Показывается NDLanguage441 с ID6003; quitRequested снимается, busy включается,
cooldown становится5. Ответ с result1 выполняет принудительный выход;
остальные ответы только снимают busy.

Первое завершение незаконченного обучения при ready1 показывает NDLanguage444
с ID6001 и снимает ready. Следующее завершение, force либо уже законченный
runtime выполняет capture-null → Avatar skip1 → current-stage virtual52 →
stage input1 → unload → Avatar stage3. Значение ответа6001 не фильтруется.
Смысл virtual52 не переименован без дополнительных доказательств.

Ответы1400/1402 устанавливают input0 независимо от результата. Сообщение1201
не закрывает briefing при close-block; нулевой LPARAM также сохраняет окно,
как в целевом CBaseBoard.1202 переключает видимость. Типы0/1 сообщений меняют
close-block только после успешной передачи настоящему rich-view provider.
При отсутствии provider они возвращают false. Успешная пустая реализация
окна0/1/4 не добавлялась.

Guide FFFF скрывает изображение. Обычный WORD становится одной парой low/high.
Если lowBYTE17, создаются две строки `{high,255}`, `{17,high}`;255 сохраняется.
Показ самих изображений ещё требует нового окна.

Выбор файла использует raceBYTE/2 → b/c/a и classBYTE → w/r/f/s. Старый runtime
выгружается до попытки чтения, затем ordinal0 и существующий общий refresh.
Подготовлены реальные bw/cr/as; проверены отказ загрузки и skip без замены
текущего сценария. Неверные индексы таблиц и переполнение пути ограничены.

## Проверка в собственном клиенте

`scripts/probe_client455_tutorial_board.py` компилирует исходник панели и
console harness с точным набором обычных клиентских объектов и библиотек.
Связи со stage/Avatar и rich-view в harness — явные тестовые получатели.
Окна `CGUIMessagebox`, их текстовые доски и D3D-отрисовка — настоящие методы
клиента. Это не запуск обучения в обычном игровом цикле.

Собственная x86 PE:
`ed4fbf9de21341e7b9a5751cc1fb3c7181e82dc54ab5e318c144dccfd4bd78f4`,
entry RVA `EBD30`, естественный exit0. Проверены IDs/styles/alpha/текст,
настоящие NDLanguage441/444, ветви выхода/блокировки, часы и три SCP-файла.
Отрисованный viewport640×480 содержит17694 изменённых пикселя. Служебные20строк
оконного backbuffer640×500 исключены из подсчёта и экспортированного кадра.
PNG осмотрен: сообщение видно, но кнопки используют старые назначения спрайтов.
Это зарегистрированное расхождение, не подтверждение внешнего вида455.

Тестовый ActionsHost из060 вынесен в `native/testing/`; production rules060
не менялись. Его короткая регрессия прошла, все99 программ снова подготовлены.
Текущие hashes этой регрессии находятся в inventory. Общий production
`RF_Online.bin` остаётся056 SHA56905e68…; широкие неизменённые suites не повторялись.
