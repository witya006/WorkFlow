# Проверка 212 — телепорт из инвентаря

В обоих закреплённых x86-бинарниках совпадают инструкции 12
проверенных функций. Обработчик предмета по RVA `0x75050` передаёт
младшие 16 бит серийного номера в запрос `4/26` длиной 2 байта
по RVA `0x1c42d0`. Ответ `4/27` по RVA `0x1c4390` принимает
коды 0 и 10, номер карты и три знаковые координаты из 8 байт.
Успешное завершение применения предмета категории 22 удаляет
одну единицу из сумки. Этот вызов сверён по RVA `0x75cf8`.
[SHA-256 и адреса двух эталонов](../inventory/client455-base-portal-reference.json)

Восстановленный обработчик читает типизированный предмет 455 из
штатной ячейки. В прежнем пути к нему применялся класс старого
инвентаря. Стек исходного ручного вылета отсутствует.
На время ожидания ответа клиент сохраняет текущую карту
привязанной для старых потребителей. При отказе, отмене или сбое
отправки разблокирует инвентарь. Переход на отсутствующую карту
не запускается.

Первая живая проверка сборки `f9d3bd6b…` воспроизвела вылет
после успешного ответа сервера. Стек указывает на `CSprite::DrawSprite`
по RVA `0x13893a` через отрисовку окна. Клиент открывал старое
окно загрузки, хотя исходная и целевая карты совпадали.
Ветвь оригинала по RVA `0x2d5b0` сверяет номера карт и
на той же карте переходит к смене позиции через 700 мс без
окна загрузки. Затем выдерживает 1300 мс. Для межкартового
окна подключён штатный `maploading.spr` через реестр спрайтов 455
с проверкой доступности кадра.

Компонентная проверка на оригинальном Item.edf прошла с первым
слотом. Штатный транспорт записал `4/26` с ожидаемым серийным
номером. Диспетчер `4/27` для кодов 0 и 10 назначил три
координаты и уменьшил количество 10 → 9. Проверены отказ,
повтор ответа, неверная длина, сбой отправки, отмена, неизвестная
карта и отсутствующий файл карты. Подтверждён переход без окна
загрузки при совпадении карт.

На сборке `1440912430386e7eb866b4f5185a42caf954d067a953e43f60db05c1f63549ac`
(x86, RVA входа `0x18c0f0`) в оконном Taiwan после применения
предмета из первой сумки, первого слота, сервер ответил успехом.
Клиент применил позицию и получил подтверждение режима 3. Прогон
завершился по таймеру без необработанных исключений. Тестовый
персонаж начал повторный прогон уже у точки назначения. Проверка
передала событие самой ячейки штатному окну клиента. Физический
клик, перенос из отдалённой точки и ходьба после прибытия открыты.
