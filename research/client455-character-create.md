# Создание персонажа в обычном клиенте — 12.11.2026

В сборке `88e4b90c…` обычные клики открыли свободный второй слот,
выбор Беллато, выбор класса и форму имени. После выбора варианта брони
и ввода имени клиент отправил `1/10` с телом в 28 байт. Локальный сервер
ответил `1/11` с двумя байтами, результат 0 и слот 1. Клиент вернулся
к списку с новым персонажем и завершился штатно с кодом 0. При повторном
входе размер ответа списка `1/9` вырос с 178 до 342 байт. Во втором слоте
отобразился сохранённый персонаж первого уровня.

Первая попытка на `68b64af3…` падала при подтверждении расы.
RVA `0x1d866` принадлежит `CPlayerClass::GetHP`. Старый поиск класса
вернул null, поскольку таблицы 455 загружаются в отдельный типизированный
владелец. Панель класса теперь берёт данные из `GetClassData455`.
Список и внешний вид персонажей используют существующие типизированные
слоты экипировки. В предварительном просмотре показан базовый FP.
Вклад мастерства Силы и отображение модели в форме имени остаются открытыми.

## Эталон 455

Основная копия x86 с базой `0x400000` имеет SHA-256
`b1b5febf0d0394712e2322350e19dafe60742e8642697b93cfb89135bac1fd8b`.

| RVA | Наблюдение |
|---|---|
| `0x3bb790` | Имя длиной до 16 байт проходит штатную проверку перед отправкой. |
| `0x16b5d0`, `0x16b570` | `1/10`, 28 байт. Слот по смещению 0, имя по 1, раса и пол по 18, код класса по 19, внешность по 24. Шесть полей внешности по четыре бита, четыре детали брони, головная деталь и лицо. |
| `0x162f50`, `0x16b740` | Диспетчер принимает `1/11`, обработчик читает два байта. Исходный обработчик инициализирует ресурсы персонажа и состояние туториала. В порте изменения ресурсов применяются при успешном ответе. |
| `0x13ab10`, `0x1faf70`, `0x1f9b10`, `0x1f9bb0` | Панель ищет класс по коду и читает исходные параметры из таблицы. Базовые HP/FP/SP начинаются по смещению 224, очки навыков по 236. У всех 11 уникальных начальных классов закреплённого набора очки навыков равны нулю. |
| `0x13da7d`, `0x13f358` | Успешное создание возвращает в выбор персонажа. Вход в обучение проверяется отдельно. |

Живой прогон использовал отдельную рабочую копию 640×500 с настройкой
Taiwan, штатный ввод Windows и тестовую учётную запись. На установке
игры и в серверных файлах правок не было. Для дальнейшей проверки нужны
пустой список на новом аккаунте, отказы создания, форма внешности и
переход нового персонажа в туториал с последующим выходом в мир.
[Манифест прогона](../inventory/client455-character-create-checkpoint.json).
