## Формат и фактический состав

Главный count — DWORD, должен быть ровно110. Затем сравнивается count NDMap.
В source-owned x86 записи сохранены размеры588/288/96/84. Поля геометрии:
552/556 — ширина/высота,560/564 — signed смещение. Остальные непроверенные
поля сохраняются побайтно; старые имена ряда полей оставлены для исходных
потребителей и не доказывают полноту их семантики. Сериализованные pointer
slots заменяются собственными выделениями.

После110 карт читаются два раздела:103 и7 записей, всего660 подписей и257919
байт изображений. ColorDWORD подписи получает OR0xFF000000, как в3B3E90.
Count локализованного дополнительного раздела читается, но не сравнивается —
это особенность эталона. Основные Map718859 и NDMap116750 байт разобраны
полностью, без остатка. Обёртки EDF каждого проверенного файла выдерживают
decode/encode round trip с полным совпадением исходных байтов.

В комплекте есть несовместимые языковые данные:

| NDMap | count | Результат закреплённого loader |
|---|---:|---|
| zh-tw |110|Принимается с корневым Map110|
| ko-kr |100|Отказ из-за несовпадения count|
| en-gb/en-id/en-ph/ja-jp/pt-br/ru-ru/zh-cn |31|Отказ из-за несовпадения count|

Это вывод о конкретных файлах и проверке клиента; он не является отдельным
доказательством региональной идентичности всей установки. Файлы не заменены,
не переименованы, отсутствующие карты не дополнены фиктивными данными.
Многоязычный полный игровой сеанс на этом наборе не принят.

В реальных записях максимум54 портала и62 зоны добычи. Старые встроенные

Остальные фиксированные буферы старых UI потребителей и протокол порталов
ещё требуют проверки; замена хранения не завершает весь этот функционал.

## Обычная сборка и проверка

CLand::LoadData читает реальные EDF и публикует собственный map owner.
Обычный UI_SetMinimap вызывает ApplyMiniMapGeometry455: signed short границы
из BSP node1, затем четыре поля выбранной карты. Сохранён target порядок
bounds→geometry и fanout на три маркера. Удалены старые таблицы восьми карт
и ограничение выбранного индекса7. Старый cut offset получает обратный знак
реального map offset; его полный avatar/UI потребитель отдельно не принят.

В обычном собственном PE декодированы реальные вызовы:

- CLand::LoadData → RF455_LoadMapData → RF455_ParseMapData.
- CLand::UI_SetMinimap → SetMapBound и SetNuclearMapGeometry455.

MSVC встроил ApplyMiniMapGeometry455 в UI_SetMinimap; отдельного символа
этой функции в обычном PE нет. Проверяется фактический вызов producer,
а не наличие имени в исходниках.

- Полные CLand UI_SetMinimap/OpenMinimapWindow, selected/special state,
  reset/sprite/avatar/portal/region/scroll/reset/device paths остаются старым
  частично перенесённым кодом. Проверен настоящий geometry provider, не вся UI цепочка.

  global layer manager consumers и их UI ещё не завершён.
- Безопасные отказы на коротком/переполненном входе и атомарный неуспешный load
  отличаются от опасных partial-state/reload/leak/OOM доменов эталона и не
  подтверждают их эквивалентность. Private ABI/все writers полей не приняты.

  с фактическим texture/ref ownership, затем продолжать world/frame и UI.
