# Обычный клиент: поза и отрисовка через обёртки 455

2026-11-05. Участок M6 номер 035. M6/M6F/M7/M9 открыты.
Результат находится в work/client455-port/normal. Базовая диагностическая сборка
и engine033 не менялись. Серверные файлы не использовались.

Подключены нормальные CRender::FrameMove/DrawCharacter/DrawCharacterMat/
DrawCharacterShadow/SetState/UnSetState/SetLight и очередь прозрачности.
Они используют уже восстановленные исходные ядра, владельца ресурсов и D3D9.
LoadMeshData регистрирует модель в настоящем менеджере CUnity; типы не приводятся
к старому ABI. SetAlpha меняет модель и все её части, SetMaterial копирует 68 байт.

Исправлен адаптер IsLoadAnimation: 455 сама вызывает загрузчик с параметром 0.
Прежняя проверка одного флага была неверной. Подтверждён и сохранён необычный
случай после ошибки: повторная проверка может вернуть true при load0==0, когда
флаг попытки +4 уже установлен. В normal потребителе это проверено явно.

## Бинарное основание

14 диапазонов и константы равны в обоих закреплённых PE32 x86. SHA-256/RVA/размеры
сохранены в inventory/client455-normal-renderer-reference.json. Инструкции,
декомпиляция и xrefs — artifacts/normal-renderer455. Рабочая IDA-сессия 1bcd6f24
закрыта; save был запрошен, returned saved=null. Новых установок не было.

| Контракт | VA / RVA |
|---|---|
| UnSetState с реальными записями D3D9 | 91CBB0 / 51CBB0 |
| SetLight, SetState | 91CDB0 / 51CDB0; 91CDE0 / 51CDE0 |
| Обёртки с координатами и матрицей | 92FE80 / 52FE80; 92FBA0 / 52FBA0 |
| Обёртка тени | 930500 / 530500 |
| Дополнительная проверка границ модели | 934F00 / 534F00 |
| Регистрация в переданном менеджере | 9313F0 / 5313F0 |
| Проверка/загрузка ANI | 9316A0 / 5316A0 |

91D320 с телом return this не является установленным UnSetState. Настоящий
91CBB0 подтверждён вызовом из ResObject в 7CD340. Он записывает конкретные
состояния и четыре единичные world-матрицы; произвольное прежнее состояние
устройства не восстанавливает.

934F00 сохраняет промежуточное скалярное произведение в float перед добавлением
plane.w. Поэтому его нельзя заменить сценовым 8C2C90: они расходятся на границе
округления. Новая функция сохраняет этот порядок x87. В повороте используется
точный double операнд из 455; учтён знак нуля при округлении вниз. Проверены
96 углов и 60 границ в 12 режимах FPU. Это конечные численные случаи, не полная
сертификация NaN/overflow/немаскированных исключений.

DrawCharacter сохраняет проверку +268, ленивую загрузку, условный model-cull,
масштаб, поворот вокруг Z и преобразование координат. Необязательная матрица
без масштаба сохраняется. DrawCharacterMat имеет отличающийся контракт проверки.
В обёртке тени исходные position/alpha не используются; масштаб берётся из
последнего аргумента. BeginShadow/EndShadow и target lifecycle ещё не восстановлены.

## Проверка настоящего пути

Все 182 объекта обычного клиентского проекта и RFClient455Facade собираются x86/MT.
Все 20 восстановленных производственных CPP Character также собираются здесь
в RFClient455Kernels.lib с теми же единственными определениями типов, что клиент
и facade. Прежние отдельные component archives в новой ветви не линкуются.
Алгоритмы скопированы побайтно из уже проверенных scripts/native; происхождение
сохраняется в normal-preparation.json. Старые бинарные component libraries не
нужны для их пересборки: используются source SHA из сохранённых отчётов.
Кадры и результаты после объединения совпали с результатом до него; исходный
снимок сравнения — inventory/client455-normal-renderer-precanonical.json.
В собственном тестовом entry используются производственные CUnity и CAnimation.
Реальный путь: регистрация BN/MESH08 → GetBone/GetMesh → ANI → FrameMove →
DrawCharacter → очередь прозрачности → D3D9 HAL.

Модель содержит 51 часть по исходному MESH08, геометрия есть у 46. Два различных
кадра позы отрисованы. Для каждого кадра результат обёртки с координатами равен
результату явной матрицы; положение ненулевое. Проверены +268, отбрасывание/допуск
по плоскостям, alpha/material и состояния после UnSetState. Кадры просмотрены.
COM device/API refs и Dmalloc после явного завершения — 0; это не измерение
всех CRT allocations. Игровые DLL не загружались, исходные EXE не запускались.

Сначала тест камеры был собран без RF_CLIENT_455_WEATHER и писал в другое
расположение полей R3 state. Исправлена именно конфигурация теста: теперь он
использует те же определения, что клиент/движок. Они записаны в runtime отчётах.

PE SHA-256, x86, entry RVA, библиотеки, MAP, кадры и вывод:
inventory/client455-normal-renderer-math.json и -gpu.json. Общий checkpoint
client455-normal-renderer-checkpoint.json — PARTIAL. Полная попытка линковки
RF_Online.bin всё ещё LNK1120: осталось 27 разных символов, других ошибок нет.
CharacterMR и принудительные unresolved не используются.

## Открытые границы и продолжение

- Эффекты/их таблицы и слоты, InitEffect, AnimationReset/RematchParent/SetEyeVec,
  SetTexPath/ImportBoundBox, BeginShadow/EndShadow, _R3CalculateTime и данные
  из inventory/client455-normal-link.json. Готовые ядра повторно не восстанавливать.
- Профилировщик оригинала, static CRT sin/cos, все специальные FP/error/OOM пути.
  Сейчас sin/cos — явно современный CRT provider; exceptions/debug log — own policy.
- blendDuration +33844 конструктор не записывает. Нормальная инициализация пока
  неизвестна; тест явно задаёт 150. До появления previous track это поле не читается.
- Полные batch/orthographic/reset/fullscreen контракты, связь culling setup с
  обычным циклом и нормальный shutdown. Shared shutdown adapter проверен явно
  после уничтожения renderer, но ещё не подключён к нормальному WinMain lifecycle.
- Это собственная камера и выбранная модель. Сравнение кадров с запущенным
  исходным клиентом 455 и вся игровая/UI/network приёмка ещё не выполнены.
