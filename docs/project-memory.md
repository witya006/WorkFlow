# Память проекта

Обновлено 2026-11-04. Актуальное состояние, не журнал команд.

## Цель

Собираемая реализация, совместимая с закреплённым клиентом RF 455. Исходная идентичность
не обещается. Графика и миграция компилятора — отдельные этапы. Оригиналы только читать.

## Подтверждено

- Git локальный без remote. IDA 9.2/Hex-Rays/Python/MCP работают; нативные вызовы
  ранее проверены на LoginServerSR.exe (669 функций). Клиент 455 полностью не исследован.
- GoMMO 2.0.1 отвечает через stdio, нативная регистрация не добавлена. Он не доказан
  эталоном CCR. Universal Modder: 13 навыков и CLI, эвристики не заменяют RF-аудит.
- Статический аудит: 14 DSP, 14 DSW, 41 CFG, 832 SOURCE; 6 отсутствующих записей
  в CameraExporter/R3MapExp. Все 962 исходных файла сохранили прежние SHA-256.
- Ни одной сборки пока нет, VC6 toolchain не найден. У клиента отсутствуют Character.h,
  требуемые варианты Character-библиотек и сторонние .lib.
- Вложенные Account/Login дублируют исходники. Каноническое дерево — внешний RF_Server.
- Серверные проекты используют ODBC; ADO-обёртки не входят в их include-цепочки.
- Полный ZoneServer и исходная схема БД не найдены в legacy-комплекте.

## Решения

- D01: первая содержательная сборка — внешний LoginServer Win32 Debug (12 C++).
  Compile/link; запуск/БД отдельно. R3MRobot — необязательная проба toolchain.
- D02: не переименовывать CharacterMR.lib в CharacterMD/R без доказанного ABI.
- D03: CRT-флаги не исправлять вслепую; сначала сохранить исходный результат.
- D04: повседневно Sol medium, реверс Sol high, Astra high для трудных локальных вопросов.

## Следующий шаг

Подготовить VC6/Win32 SDK среду и копию LoginServer, получить чистую сборку M1.
Если toolchain недоступен — продвигать статические эталоны клиента M2.
Порядок: next-steps.md; блокеры: build-audit.md; этапы: roadmap.md.

## Неизвестное

Различия текущего клиента/backup; точная версия SDK/CRT; Character SDK и сторонние .lib;
полный сервер мира; схемы/процедуры БД; первый формат для эксперимента M3.
