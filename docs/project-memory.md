# Память проекта

Обновлено 2026-11-04 после уточнения пользователя: ИСКЛЮЧИТЕЛЬНО КЛИЕНТ.

## Цель и границы

Восстановить исходники и собираемый клиент RF Online 455 на основе старого клиентского
кода, R3Engine и реверса клиента 455. R3Engine/утилиты входят в работу как зависимости
клиента. Серверные проекты, БД и серверная логика вне задачи. Их отсутствие не блокирует
клиентскую работу. Перенос под современный MSVC выполняется сейчас; графика отдельно.
Оригиналы читать.

Уточнение пользователя: конечный результат — исходный код RF_Online.bin с полным
функционалом и поведением эталона 455, а не только собирающийся старый клиент.
Промежуточная сборка/первый формат не закрывают проект. Полноту подтверждать реестром
возможностей, сценариями и расхождениями: client-acceptance.md.
Серверные исходники можно читать как справочник; изменять или собирать их нельзя,
включая копии. Их описание не доказывает поведение клиента 455.

## Решения

- D01 отозван: выбор LoginServer для первой сборки был ошибкой области задачи.
- D01C: первая цель сборки клиентской зависимости — R3Engine - Win32 RTMovie Release.
  В её CPP-флагах нет RTMOVIE; достижимость Character-зависимости проверить препроцессором.
  Эта конфигурация создаёт R3Engine.lib и не удовлетворяет автоматически клиентскому
  требованию R3EngineMT.lib. Это первый шаг восстановления сборки, не готовый клиент.
- Конечная цель сборки — RF_Online, после проверки Character/CRT/прочих библиотек.
- D05: основной путь — сразу VS 2026/MSVC x86, без обязательной установки VC6.
  Старые DSP сохраняются как справочник настроек. DirectX/рендер пока не модернизировать.
- CharacterMR.lib не переименовывать в CharacterMD/R без проверки символов и ABI.
- Повседневно Sol medium; реверс Sol high; Astra high для трудных локальных вопросов.

## Следующий шаг

Активная цель по /Goal, уточнённая пользователем: пройти M1–M4 и сообщить при
переходе к началу M5 «Первый участок 455». Это включает полную сборку RF_Online
в M4; прежний ориентир на начало пункта 4 отменён последующим уточнением.

M1 выполнен; бинарный эталон и различия M2 закреплены. M3 выполнен для helper-only
SPT: 140 реальных файлов / 97 543 объекта, побитовое float32 round trip и 7 unit-тестов.
Детали: research/helper-spt-format.md, inventory/helper-spt-verification.json.
M4 начат: современная цель RF_Online содержит все 180 C++ исходников Release;
первая компиляция завершилась с 1: 93 .obj, 87 C1083, только Character.h и Winable.h.
Очищенная диагностика inventory/client-executable-build-result.json. Нужны Character SDK/типы,
сторонние библиотеки и согласование CRT. См. research/character-library.md.
Из библиотеки извлечены 224 публичных контракта и 10 COFF объектов. IDA member_06.obj
показала первые смещения ChInterface/CHARACTEROBJECT; сессия e76a265d сохранена/закрыта.
Следующий шаг: восстановление контрактов Character по символам/коду/использованиям,
проверка замены устаревшего Winable.h современными декларациями Windows SDK.
По просьбе пользователя проверены файлы 455 и серверные справочники. Серверных
определений render-классов не найдено. В 455 найдены связанные функции; подтверждён
статический импорт Direct3DCreate9, в отличие от D3D8 старого Character SDK.
Восстановлены 2 GPU vertex layouts (64/36 байт), MSVC x86 probe проверил offsets/enums
и все 96 байт деклараций. Это не CPU Character.h. Детали research/character-455-recovery.md.
Winable.h заменён на windows.h только в рабочем protect.cpp. Выборочная компиляция
прошла это включение и остановилась уже на Character.h; код защиты не менялся.
Все собственные IDA-сессии закрыты; актуальные выгрузки в artifacts/.
Ориентир пользователя — сообщить при переходе к началу M5; до него ещё не дошли.
Полный хеш-манифест ресурсов и атрибуция версии ещё открыты.

Дополнение M4: через IDA MCP выгружены 207 определений функций Character из 10 COFF
объектов (повторные inline учитываются отдельно), extern отфильтрованы по COFF.
Выгрузки кешируются в artifacts/character-analysis, повторный реверс не нужен.
21 проверка операндов инструкций подтвердила выделение CHARACTEROBJECT 776 байт,
ChAnimation 280, шаг ObjectMesh 1072; поля count/mesh/alpha/material/эффектов и
первые поля CObjectManager. Частичные memory views под work/recovered/character-legacy
прошли native MSVC x86 static_assert; это ещё не Character.h и не контракт CPU 455.
4 теста COFF/границ/инструкций прошли. Манифест character-legacy-layouts.json.
Проба link-only GetAlpha со старой CharacterMR оставляет std::_Xlen и std::_Xran;
не выполнялась. Совместимость контейнеров/CRT/исключений пока не доказана, заглушек нет.
Следующий шаг: размеры ChInterface/менеджеров, встроенные поля и конструкторы по
локальным выгрузкам и обращениям клиента. Подробности research/character-library.md.
