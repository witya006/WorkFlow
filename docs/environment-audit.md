## IDA и MCP: обнаруженные препятствия

На момент начала аудита процесса IDA и слушающего MCP-сервера IDA не было.
В текущем наборе инструментов чата нет IDA. В пользовательском config.toml Codex
нет регистрации IDA/GoMMO; mcp.json LM Studio не содержит настроенных серверов.

Проверены:

- `C:\Program Files\IDA Professional 9.2\plugins`;
- `C:\Users\Admin\AppData\Roaming\Hex-Rays\IDA Pro`;
- `C:\Users\Admin\AppData\Roaming\Hex-Rays\IDA Pro\mcp\instances` — пусто;
- стандартные `.idapro` и `AppData\Roaming\IDA Pro` — отсутствуют;
- несколько обычных мест расположения `ida-pro-mcp` — не найдены.

Файлы MCP-плагина в проверенных местах не обнаружены. Это не утверждение, что
архива или другой установки MCP нет нигде на ПК. Необходимо установить его
фактический путь и реализацию перед настройкой.

Скрипт `scripts/probe_ida.py` копирует старый `LoginServerSR.exe` в `work/ida-smoke/`
и запускает только статический анализ через idat.exe. Сам серверный EXE не запускается.
В песочнице IDA завершилась с кодом 2 без диагностического лога. Повтор вне песочницы
завершился с кодом 1 и дал диагностический лог:

```text
failed to load Python runtime: skipping IDAPython plugin
Hex-Rays Decompiler plugin has been loaded (v9.2.0.250908)
.../scripts/ida_smoke.py: unknown file extension
```

PE x86 загружен в базу; IDAPython-скрипт не исполнен. Реальная декомпиляция функции
не подтверждена. IDA также автоматически попыталась найти PDB на Microsoft symbol
server; PDB не найден. Параметры символов для будущего стенда следует фиксировать.
Сырые логи и промежуточные базы оставлены только в игнорируемом `work/ida-smoke/`.

Для исправления сначала выбрать устойчивую установку поддерживаемого Python,
проверить её через `idapyswitch --dry-run`, затем привязать IDAPython и повторить
проверку. Встроенный Python Codex годится для аудита, но его кэшируемый путь не
выбран автоматически как постоянная системная зависимость IDA.
