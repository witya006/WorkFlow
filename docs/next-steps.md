# Следующие этапы

## 1. Подготовить IDA к автоматизации

- Найти фактический комплект установленного пользователем IDA MCP и определить его версию.
- Восстановить Python runtime для IDAPython через проверяемую постоянную установку.
- Повторить `scripts/Invoke-Python.ps1 scripts/probe_ida.py`.
- Критерий: IDAPython отработал, получено число функций и декомпилирована хотя бы одна функция PE x86.
- Проверить MCP handshake, список инструментов, чтение метаданных базы, списка функций
  и одной декомпиляции. Использовать схемы конкретной реализации MCP.
- Затем подключить проверенные серверы к Codex. Пример GoMMO уже подготовлен.

## 2. Проверить собираемость старого комплекта

- Сопоставить SOURCE в 14 dsp с реальными файлами, разобраться с дубликатами серверов.
- Проверить зависимости R3Engine, CharacterMR, Miles, DX8.1, ADO и SDK экспортёров.
- Определить наличие исходников игрового сервера мира и схемы БД.
- Подготовить отдельную среду VC6 и зафиксировать версии/параметры сборки.
- Критерий: воспроизводимая сборка компонента либо точный список недостающих входов.

## 3. Создать эталоны анализа

- Скопировать эталонный backup клиента в work/, проверить SHA-256 после копирования.
- Создать отдельные базы IDA для оригинала и текущего изменённого клиента.
- Определить разницу этих двух файлов до сопоставления с версией 0.7.
- Зафиксировать базовые адреса, импорты, строки и признаки toolchain.
- Подготовить автономный тестовый стенд; текущий пакет GoMMO не объявлять
  оригинальным сервером CCR и не принимать всё его поведение за эталон.

## 4. Провести ограниченный эксперимент

- Выбрать один формат таблицы/ресурса с исходным загрузчиком и образцами 455.
- Найти соответствующий код, описать изменения и реализовать отдельный парсер.
- Проверить несколько реальных файлов и обработку некорректных входов.
- По результату определить объём следующего этапа; графическую модернизацию вести отдельно.
