## Следующий результат: сборка клиентской зависимости

Начато: 492 файла клиента/движка скопированы и проверены, CMake configure прошёл.
Первая компиляция дала 12 COFF x86 объектов; итог exit 1. Теперь ближайшая задача —
DirectX 8 headers и C2065/C7732 (область видимости i в common/cjcache и commonutil).
Базовый результат: [первая сборка](../research/client-port-first-build.md).
Команды: Invoke-Python.ps1 scripts/prepare_client_build.py, затем build_client_engine.ps1.

Основная среда — VS 2026 Professional 18.11.3 / MSVC 14.51.36231 / Windows SDK
10.0.26100.0 / CMake 4.3.1-msvc1. Собственный Win32 x86 smoke собран и запущен.
VC6 не требуется для начала; использовать только при доказанной необходимости.

1. Продолжить проверку R3Engine - Win32 RTMovie Release: фактические макросы, include-цепочки,
   CRT и внешние SDK. Название конфигурации не доказывает наличие макроса RTMOVIE.
2. Создать современный проект/CMake для R3Engine под установленный MSVC x86;
   проверить пригодный DirectX SDK. Сохранить исходные макросы/CRT как предмет анализа.
3. Копировать только клиентское дерево и R3Engine под work/client-build, сохраняя байты.
4. Перенести настройки RTMovie Release, исправить несовместимости компилятора,
   собрать R3Engine под MSVC 2026, проверить выход R3Engine.lib
   и повторную чистую сборку. Архив библиотеки проверить по COFF machine, не как PE EXE.
5. Отдельно согласовать библиотеку движка с клиентом: RF_Online требует другой вариант
   R3EngineMT.lib. Проверить символы/CRT, не переименовывать библиотеку вслепую.

## Восстановление клиента

- Закрыть Character.h, CharacterMD/CharacterR и сторонние .lib, include/link/CRT.
- Цель последующей полной сборки — RF_Online; сборка движка не считается её заменой.
- Сделать копии RF_Online.bin и backup, сверить хеши, создать отдельные базы IDA.
- Локализовать различия, закрепить эталон 455.
- Развернуть реестр возможностей эталона: сценарии, ожидаемое поведение,
  подтверждения и расхождения с восстанавливаемым клиентом.
- Выбрать один формат с клиентским загрузчиком и реальными образцами; описать,
  реализовать и проверить парсер, затем интегрировать в восстановленный клиент.

Проверки сетевого поведения относятся только к клиентским пакетам и состояниям.
Разработка серверов, восстановление БД и серверной логики в план не входят.
Серверные исходники разрешено читать как справочник, без сборки и изменений;
относящиеся к клиенту выводы проверять по эталону 455.
Современный toolchain теперь доступен; остаются зависимости и перенос клиентского кода.
